# Раздел New: layout'ы каталога VK X

Перенос отображения блоков `catalog.getAudioAuto` из VK X. Экран —
`app/src/main/kotlin/com/lmg/vk/ui/screens/NewScreen.kt`, данные приходят
через `HomeViewModel` → `HomeBlock` / `HomeItem` (`BackendModels.kt`).

## Что определяет вид блока

Ключ — `layoutName` в `HomeBlock`, он же поле `layout.name` в ответе VK.
Подтверждено адаптером VK X `Catalog2LayoutJsonAdapter`: там полиморфный
разбор построен именно по `"name"` (`new C2065e(clazz, "name", …)`), а не по
`style`. Значит наш парсинг (`block.layout?.name`) верен.

Полный реестр адаптера — **43 имени**. Ниже карта тех, что относятся к музыке;
служебные (`artist_header`, `owner_cell`, `link_snippet`, `podcasts_favorites`,
`music_newsfeed_title` и прочие) либо отсекаются раньше в `MusicBackend`, либо
попадают в пропуск/общую карусель.

### Главное: `slider` — самый частый layout

Именно им VK отдаёт основную часть подборок. Он не имеет отдельной ветви и
попадает в `else`, поэтому раньше **весь экран выглядел одинаковыми мелкими
квадратами**, даже когда батчи 1-2 уже добавили крупные карточки: блоков
`large_slider` и прочих в реальной выдаче просто мало. Теперь для `slider`
(и для пустого `layoutName`) карточка в общей карусели рисуется широкой —
172dp вместо 140dp, в компакте 138 вместо 110.

## Батч 3 — почему на экране были только квадраты

Симптом: после батчей 1-2 экран всё равно выглядел как однотипные мелкие
плитки. Причина не в вёрстке — новые карточки предназначены для
`large_slider`/`music_chart_large_slider`, а таких блоков в живой выдаче
мало. Основную часть VK отдаёт обычным `slider`, который падал в `else`.

Сделано:

- **`slider` рисуется широкой карточкой** (172dp, компакт 138dp) — параметр
  `wide` у `NewTrackCard`. То же для пустого `layoutName`.
- **Реестр расширен по адаптеру VK X**, а не по догадкам: в крупные слайдеры
  добавлены `audio_stream_mix`, `audio_stream_mix_interactive`; в сетки —
  `categories_list`, `podcast_category_genre_buttons`, `horizontal_buttons`.
- **`NEW_SKIPPED_LAYOUTS`** — технические блоки (`separator`,
  `in_block_separator`, `placeholder*`, `text`, `music_newsfeed_title`,
  `playable_item_in_progress`) не рисуются вовсе: карточками они выглядели бы
  мусором. `header*` отсекается раньше, в `MusicBackend`.
- Подтверждено, что `banner`, `list`, `listened_list` реально существуют в
  реестре VK X — раньше они были нашим допущением.

Итого явно обработано 37 имён из 43; остальные — служебные, деградируют в
карусель.

## Батч 1 — что сделано

Три новых компонента, все в стиле экрана (`AlbumArtImage`, `LiquidTheme.colors`,
`AppFontFamily`, компактный режим множителями):

- `NewLargeCard` — обложка 4:3 (248×184, компакт 190×140). Смысл не в размере:
  широкая карточка вмещает в экран меньше элементов, и именно этим VK выделяет
  «большие» блоки среди обычных каруселей. Номер чарта рисуется, если
  `layoutName` начинается на `music_chart`.
- `NewExtendedCard` — квадратная обложка, подзаголовок в две строки: у VK это
  блок с описанием, одной строки не хватает.
- `NewDoubleGrid` + `NewGridTile` — горизонтальная прокрутка, но элементы идут
  парами по вертикали (`chunked(2)`), порядок читается слева-вниз-вправо, как
  в оригинале. Плитка — обложка слева, подписи справа.

Наборы имён вынесены в `NEW_LARGE_SLIDER_LAYOUTS` и `NEW_GRID_LAYOUTS`;
пересечений между всеми наборами нет, поэтому каждый layout попадает ровно в
одну ветвь `when`. Подписи в шторке «показать все» дополнены в
`newLayoutLabel` (чарт / эксклюзив / рекомендации / сетка / жанры).

## Что осталось (батч 2)

Баннерное семейство (`podcast_banners_slider`, `smart_banner`) ложится в
существующий hero-путь почти без нового кода. Два пункта требуют решений:

- `close_catalog_banner` — нужен крестик и запоминание закрытия
  (`SharedPreferences` по id блока), иначе баннер вернётся после перезапуска;
- `subsection_tabs` — структурный: это не карточки, а переключатель
  подразделов внутри блока, каждому табу соответствует своя выдача.

## Батч 2 — что сделано

- **Баннерное семейство расширено**: `podcast_banners_slider`, `smart_banner`,
  `crop_slider` добавлены в `NEW_HERO_LAYOUTS`. Отдельной вёрстки не требуют —
  у VK это те же широкие баннеры.
- **Попутно исправлена потеря элементов.** Hero-ветвь брала `items.first()`, то
  есть у *слайдерных* баннеров (а это `promo_banners_slider` и остальные с
  суффиксом `_slider`) все элементы кроме первого молча терялись. Теперь при
  `items.size > 1` рисуется `NewBannerRow` — карусель, где ширина карточки чуть
  меньше экрана, поэтому виден край следующей и понятно, что блок листается.
  Единственный баннер по-прежнему занимает всю ширину.
- **`NewCloseableBanner`** — крестик поверх обложки. Закрытие переживает
  перезапуск: id закрытых блоков лежат в `NewDismissedBanners` (отдельный файл
  prefs `new_dismissed_banners`, не в `AppSettings` — это состояние выдачи, а не
  настройка пользователя; смешивать значит однажды выгрести чужие ключи при
  сбросе настроек). Список ограничен 60 записями: VK меняет id блоков, и без
  предела ключ рос бы бесконечно. Закрытый блок скрывается вместе с заголовком,
  иначе осталась бы пустая секция.

### `subsection_tabs` — сделано частично, и это осознанно

У VK каждому табу соответствует **своя выдача**, приходящая отдельным запросом
по идентификатору секции. Такого запроса в порте пока нет, поэтому табы
работают как навигация по элементам самого блока: выбранный раскрывается ниже
баннером. Полноценный вариант потребует метода загрузки секции по id — это
отдельная работа на стороне `HomeViewModel`, не UI.

Ставить неработающий переключатель было бы хуже: он выглядел бы как настоящий.

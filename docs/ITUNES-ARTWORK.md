# Обложки и моушен: Apple Music → iTunes → VK

## Исправление Bruised Skу — 2026-09-24

В серверном кэше обнаружены реальные запросы телефона: `title=bruised skу`, `artist=poppy`, `duration=220.75`/`221`, `album=single` либо пустой. Последний символ в `Skу` — U+0443 CYRILLIC SMALL LETTER U, а не ASCII y. Предыдущие проверки вручную использовали ASCII Sky и не воспроизводили этот случай. До исправления точный запрос вернул `not_found`; после исправления — Bruised Sky / Poppy, 220837 ms, обложку и motion, за 0,80 секунды.

В нормализации клиента и серверном `artwork_matching.py` исправляются только смешанные латинские слова с известными кириллическими двойниками. Целиком кириллические слова не транслитерируются; текст в интерфейсе не изменяется. Версии Live/Remix и проверка артиста остаются обязательными. Нормализованный запрос получает другой ключ кэша, поэтому прежний промах `skу` не нужно ждать 15 минут или очищать данные приложения.

После жалобы на исчезновение переходов проверены все 14 хешей из `motion-sheet-morph-2026-09-23/sources.sha256` и `frozen.sha256`: совпали, включая FullPlayer, LyricsScreen, QueueSheet, renderer, playback и геометрию. В ранее отправленной APK (SHA256 01d7f177...) также присутствуют motionToSheetThumbnail, motionFrameReveal, MotionSheetClip, lyricsOpacity и queueOpacity. Это подтверждает сохранность кода, но не заменяет проверку переходов на телефоне. У пользователя уточнено, наблюдается ли проблема на треке с работающим motion.

Проверки исправления: 64 artwork-теста, 13 тестов геометрии/возврата экранов и 13 серверных тестов прошли. Новая [APK bruised-sky-fix](https://drive.google.com/file/d/1ID-uLa5ZNjyjkGZf_LvNg17dgrFswZ7O/view): SHA256 `5ee7115969fef21ec2c3e902b83d7bf99e6d9c7105466c99c2429cd6c1f26dbd`, MD5 `9f3f111e900196cde4d4360d665e47e0`, 196087867 байт. ## Актуальная схема — 2026-09-24

Обложка и моушен получают метаданные одним запросом к московскому `/v2/motion`, с клиентским API-ключом. `AppleArtworkRepository` объединяет одновременные запросы, держит общий RAM/disk-кэш и ограничивает параллелизм тремя запросами. Передаются нормализованные название/исполнитель, известная длительность и альбом. `include_mp4=0` убирает ненужное извлечение MP4 на сервере: Android использует HLS. Если у подтверждённого результата нет картинки, статическая обложка ищется через iTunes; VK/локальная обложка доступна во время ожидания.

Проверяется идентичность трека, включая версии Live/Remix; регистр, диакритика и feat допускают нормализацию. Неизвестная длительность не блокирует поиск. Apple-результат с известной длительностью проверяется с допуском 6 секунд, резервный iTunes — 3,5 секунды. Проверен пример SÃO PAULO → São Paulo / The Weeknd & Anitta.

Из Apple CDN запрашивается 1200px rendition без предварительного скачивания оригинала и 10000px картинки. Coil загружает выбранный URL и использует собственный кэш. Общие метаданные и найденная обложка хранятся сутки, подтверждённые промахи — 15 минут. Сбой сети/авторизации/разбора не сохраняется как отсутствие обложки. Введены новые каталоги metadata-кэша v3; кэши видеосегментов и Coil сохраняются. В DebugLog видны cache source, время, наличие cover/motion и ошибки поиска.

Проверка новой реализации: Gradle `:app:testDebugUnitTest --tests com.lmg.vk.artwork.* :app:assembleDebug` завершён успешно, 62 artwork-теста без ошибок; 11 серверных тестов также прошли. APK подписана, новые endpoint/cache/query классы проверены в DEX. На телефоне новая сборка ещё не проверялась.

Изменения серверной части, тесты и результаты живых проверок сохранены в `scripts/artwork_server/`. Рендерер, фон, геометрия и жизненный цикл воспроизведения моушена этим изменением не затронуты.

# Обложки песен из iTunes

2026-09-21: владелец явно разрешил отдельный источник обложек и задал порядок: совпадение iTunes → обложка ВК → сгенерированный VK thumb. Это исключение из старого правила VK-only только для изображений, не для музыкальных потоков.

## Поведение

Исходные VK URL и модели не перезаписываются. Готовый результат из памяти используется в первом кадре. Пока выбор для новой песни не завершён, показывается нейтральное место загрузки; временная обложка ВК не показывается. После поиска появляется сразу выбранная обложка iTunes либо окончательный VK fallback. Существующий `AudioTrack.coverUrl()` сохраняет порядок `album.thumb → track.thumb`. Если отсутствуют оба источника, остаётся прежний нейтральный значок; новый thumb приложение не выдумывает.

Поиск: HTTPS iTunes Search API, витрина US, entity=song, limit=25. Совпадают нормализованные название и набор исполнителей (поддержаны feat/ft/featuring/п.у. и разделители коллабораций). Допустимая разница длительности — 3 секунды; без известной положительной длительности поиск не выполняется. Обозначения Live/Remix/Sped Up и другие версии не удаляются для принудительного совпадения. При выборе в приложении название альбома ВК не участвует: один и тот же трек на разных экранах может иметь разные или пустые подсказки альбома. Из подходящих результатов выбирается ближайшая длительность. Это консервативное сопоставление, не гарантия определения первоначального издания.

Качество: сначала проверяется исходный Apple asset через `a5.mzstatic.com/us/r1000/0/`, затем rendition `10000x10000bb.jpg`, затем URL из API. Преобразуются только HTTPS URL поддоменов mzstatic.com с путём `/image/thumb/`. Это проверенные на живом CDN варианты, а не обещание Search API для любого изображения. UI декодирует картинку под размер элемента, файл в дисковом кеше сохраняет исходные байты. При недоступности всех вариантов остаётся ВК.

Поиск/JSON/диск вне main thread. В поиске запрос iTunes стартует параллельно с запросом VK; его кандидаты повторно используются для строгого сопоставления строк выдачи. Разные VK-копии с тем же названием/артистами не требуют отдельных сетевых запросов, если подходит уже полученный кандидат. Отсутствие совпадения в общей выдаче не считается доказательством отсутствия конкретного трека. Общие запросы объединяются; после ухода последнего потребителя ожидание/HTTP отменяется. Интервал между поисками минимум 3,2 секунды, при HTTP 429 — дополнительная пауза 60 секунд. Массового обхода всей медиатеки нет: запрашиваются показанные песни и текущий трек. Поэтому новый большой список заполняется постепенно.

Кеш: успешное соответствие 7 дней, отсутствие совпадения 12 часов, сетевые/графические ошибки 5 минут. До 1000 записей в памяти и 2000 файлов в cacheDir. Изображения используют общий Coil cache. Смена запроса сбрасывает результат; обложка предыдущего трека не публикуется для нового.

Подключены обложки песен в поиске, библиотеке/скачанных и локальных списках, карточках каталога, истории/плейлистах через общий ряд, очереди, меню трека, мини/полном плеере, палитре и фоне, сниппетах и MediaSession. Обложки самих альбомов/плейлистов и фото артистов остаются своими. В альбомном списке сохранены номера вместо картинок. При новых скачиваниях выбранная обложка вшивается в MP3/M4A до экспорта в публичные «Загрузки». Ранее скачанные файлы автоматически не переписываются.

## Проверка и ограничения

JVM-тесты проверяют соответствие исполнителей через разные поля feat, отказ от другой версии/исполнителя/длительности, нормализацию, выбор альбома и отсутствие безопасного URL. Также запускается существующий CatalogArtworkTest для VK fallback. Android UI и MediaSession на устройстве не проверялись, эмулятор не использовался.

Живой запрос `Lady Gaga The Dead Dance` вернул альбом MAYHEM и сингл; вариант 600×600 успешно скачан и проверен как изображение. Артефакты проверки и сборки: `/root/LMG-previews/itunes-artwork-2026-09-21/`.

Условия Apple не признаны автоматически выполненными: ранее пользователю объяснено, что Search API предоставляет promotional content с ограничениями, а доступность URL не является безусловной лицензией для стороннего плеера. Эта реализация не решает вопрос разрешения/оформления распространения приложения.

Официальная документация:
- https://developer.apple.com/library/archive/documentation/AudioVideo/Conceptual/iTuneSearchAPI/Searching.html
- https://developer.apple.com/library/archive/documentation/AudioVideo/Conceptual/iTuneSearchAPI/UnderstandingSearchResults.html
- https://performance-partners.apple.com/resources/documentation/itunes-store-web-service-search-api/

Работа над лагами остаётся приостановленной: рендерер лирики, пружины, растяжения и аудиокроссфейд не изменялись.


## 2026-09-21 — исправление рассинхрона обложки и фона

Владелец показал Godzilla: на «Волне» красная обложка, в полном плеере Side B, фон также не соответствовал карточке. Причина в коде: карточка Wave запрашивала `ArtworkQuery(title, artist, duration)` без альбома, а AppRoot и палитра Wave — запрос с `Track.albumName`. Разные ключи кеша и предпочтения альбома допускали разные результаты для одной песни. По одним скриншотам нельзя доказать, что Side B обязательно пришла из ВК: разные издания есть и у Apple.

Теперь repository приводит все запросы к одному виду (нормализованные название и набор артистов, длительность; без подсказки альбома). Этот же ключ используется в UI. Новый namespace `itunes_artwork_v2` не читает старые несовместимые соответствия; очищать данные приложения не требуется. Кеш самих картинок Coil сохраняется.

AppRoot владеет единственным выбранным URL текущей песни и передаёт его через `ProvidePlayingArtwork`. Мини-плеер, полный плеер, Wave и компоненты с запросом этой же песни используют общий результат. Главная карточка Wave и её палитра получают непосредственно один `waveTrackCover`; отдельного поиска картинки у неё больше нет. FullPlayer уже передаёт свой resolved source картинке, палитре, фону и AirPlaySheet.

Регрессионные JVM-тесты воспроизводят разные подсказки альбома и размещение feat в разных полях, проверяют общий выбор, fallback и отсутствие переноса на другую песню/версию. Устройство/эмулятор не использовались. Артефакты, исходники до изменения и хеши: `/root/LMG-previews/itunes-artwork-sync-2026-09-21/`.


## 2026-09-22 — показ обложки без видимой замены VK → iTunes

Пользователь сообщил, что в поиске Eminem Godzilla сначала видит VK-картинку, а примерно через 2 секунды другую. Причина: `rememberTrackCover` возвращал fallback до завершения `produceState`, даже при наличии готового кеша. Теперь готовность отделена от отсутствия совпадения (`ArtworkLoadState`). Положительный и отрицательный memory cache читаются синхронно без диска/сети; состояние привязано к запросу и fallback через Compose key. Pending не раскрывает исходную картинку. Общий выбор текущей песни передаёт готовность; Root/Wave/landscape не обходят её через старый URI. У поисковых и других строк с artworkQuery отключено дополнительное проявление Coil.

Убрана повторная проверка 600px изображения на каждом UI-потребителе: repository уже проверяет новый URL до сохранения. Изображения и сохранённые соответствия продолжают использовать существующие кеши без сброса v2. Дисковое попадание после перезапуска может дать короткий нейтральный кадр, но не промежуточную обложку ВК.

Поиск iTunes для введённого текста выполняется одновременно с VK. Пул из максимум 128 ответов живёт в процессе 12 часов, используется только через прежнее строгое сопоставление. Пустой общий ответ не блокирует точечный поиск. Между сетевыми запросами сохраняется интервал 3,2 секунды и backoff 429. Результаты VK ждут завершения prefetch не более 150мс. Когда длительности отсутствуют, существующий batch metadata-запрос выполняется до показа выдачи с пределом 1200мс: поздняя длительность больше не запускает замену уже показанной обложки. Изменение/очистка текста отменяет старый поиск и его prefetch; отмена не публикует старую выдачу.

Первый незакешированный поиск всё ещё зависит от интернета и ограничений iTunes. Мгновенное появление картинки для любой новой песни не обещается; гарантируемая логикой цель — отсутствие промежуточной картинки VK во время поиска iTunes. Порядок источников и строгие условия совпадения сохранены. Полевое время загрузки и UI на HONOR пока не измерялись.

## 2026-09-22 — очистка запросов и устаревшие отрицательные результаты

По сообщению пользователя сервер /v2/motion уже очищает VK-теги, ищет альбомный motion для сингла и возвращает ORDINARY LOSS has_motion=true. Клиент ранее отправлял сырые поля и удерживал отрицательные ответы12часов. Исправления включены в новую сборку; полная проверка и ссылка приведены ниже.

Общий ItunesArtworkMatcher очищает скобочные vk.com/vk.ru/vkontakte.ru ссылки и bitrate-теги, а известный жанровый хвост вроде Electronic удаляет только после такого служебного тега. Реальные названия Electronic/Pop и версии Live/Remix/Sped Up/Radio Edit сохраняются. Очистка применяется и при формировании запроса, и при сравнении с ответом. canonical.album теперь сохраняет очищенный нормализованный альбом; shared ArtworkSelection по-прежнему сравнивает идентичность песни без album, чтобы не разделить обложку игрока и остальных экранов.

Motion запрашивает canonical.title/artist и непустой canonical.album. Album передаётся от текущего/следующего Track и учитывается в ключе metadata. iTunes использует ту же очистку, включая предварительный поиск; совпадение по длительности±3с и версиям не ослаблено.

Добавлен lookupVersion=1 для записей обоих metadata-кешей. Старые отрицательные записи без версии игнорируются при чтении даже до expires; новый запрос перезаписывает их. Валидные старые положительные записи принимаются там, где ключ совпадает. Новые промахи —15мин вместо12ч; ошибки загрузки картинки/iTunes сохраняют короткий5минTTL.
